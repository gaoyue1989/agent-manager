# 审批提交流程规范（Standard Approval Workflow）

本技能规范化模型服务申请的完整提交流程。**你必须严格按照下述阶段顺序执行。**
每一个阶段完成后再进入下一阶段；前置条件不满足时禁止执行后续工具。

## 阶段 1 — 收集用户输入

- 收集以下三项信息，**缺一不可**：
  - **title**：申请标题（一句话概括申请内容）
  - **description**：申请文本（申请理由、用途说明、期望的服务规格等）
  - **file_links**：相关文件链接列表（可无，缺省为空数组）
- 用户零散给出时，先复述确认再落单；信息缺失时**逐项追问**，不得猜测填充。
- **禁止**把用户未提供的文件链接编造成任何形式的内容。

## 阶段 2 — 创建申请单

- 调用工具：`create_application`
  - 参数：`title` = 申请标题，`description` = 申请文本，`file_links` = 文件链接数组（可为空数组 []）
- 工具返回的 `application_id` 是后续所有步骤的唯一凭证，**务必记录并在每一步复用**。
- 创建失败（返回 isError=true）时：向用户说明错误原因，回到阶段 1 补齐信息后重试。

## 阶段 3 — 展示表单确认卡片

- 调用工具：`show_application_form`（参数 `application_id`）
- 调用后界面上会出现一张**表单确认卡片**，显示申请标题、申请文本与文件链接，
  用户需核对后在卡片上点击「确认表单」。
- **等待用户在卡片上确认，不要代替用户确认，也不要询问"是否确认"后自行确认。**
  卡片确认结果会以"表单已确认"的上下文提示注入，或由用户用自然语言明确告知。

## 阶段 4 — 阶段 3 通过后，等待用户指示提交

- 确认流程必须满足**至少一条**：
  1. 收到上下文注入的"用户已在表单卡片上确认…"提示；或
  2. 用户明确说出「确认」「确认提交」「提交申请」等指令。
- 满足后向用户复述申请要点，并请用户确认进入人工审批。

## 阶段 5 — 提交申请（人工确认）

- 调用工具：`submit_application`（参数 `application_id`）
- 此工具调用会触发**人工审批确认**，界面上会出现确认卡片/弹窗，需用户批准后才会真正提交。
- 若工具返回"尚未确认表单"错误，回到阶段 3 重新展示表单卡片让用户确认。
- 提交成功后向用户汇报最终结果（申请单号 + 申请内容 + 状态）。

## 兜底规则

- 任何工具调用失败：向用户说明失败原因和下一步，不重试编造的参数。
- 用户中途修改申请内容时：回到阶段 1，重新收集并调用 `create_application` 创建新申请单，
  或按用户要求放弃本次申请。
